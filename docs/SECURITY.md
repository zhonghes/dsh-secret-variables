# 安全模型（威胁模型）

这份文档说明「密钥管理」**保证什么、不保证什么**。日志与提示词里不要写"模型无法获取"——那不是事实。

## 保证

1. **值不进入模型可见内容**：提示词、会话日志、工具结果的明文、会话标题/摘要、导入导出里都不会出现已登记密钥的值——前提是它满足脱敏下限（≥12 字符，或开启强制脱敏时 ≥4 字符）；短值被命令主动打印的情况见「不保证」第 3 条。
2. **值不经过本插件的接口**：`/api/secret-variables` 只返回元数据、"是否已设置"与脱敏状态（`auto` / `forced` / `none`，不含量、不含长度）；值只经 Host 凭据服务读写。
3. **值不落进元数据存储**：`$DSH_HOME/storages/sensitive-vars.json` 只存名称、作用域、开关与强制脱敏标记，不含值；值在 `$DSH_HOME/.credentials.yaml`（0600）与进程内存。
4. **工具输出做精确匹配脱敏**：已启用且长度 ≥12 的值会被替换成 `$DSH_SECRET_<名称>`；符合已知凭证格式的串（清单见 README「自动检测」一节）会被替换成 `$DSH_SECRET_AUTO_n`。标记「强制脱敏」的值按 ≥4 字符参与输出替换（注入始终进行，与该标记无关）。
5. **自动检测值仅内存**：兜底变量不写凭据文件，进程结束或插件重载即消失；每个会话默认最多 16 条。

## 不保证（重要）

1. **拥有 shell 的 agent 可以主动读取值**。值按设计注入 bash/pwsh 子进程的环境变量；模型可以执行任意变形命令绕过精确匹配脱敏，例如：
   ```
   printf %s "$DSH_SECRET_X" | base64
   ```
   任何编码、拆分、逐字符、HTTP 外发都属于此类。脱敏只防"明文原样出现"，不防"主动取"。
2. **同用户进程边界**：bash 以当前用户运行，理论上可读 `$DSH_HOME/.credentials.yaml`。本 profile 的沙箱可能阻止该路径，但沙箱配置变化后不成立，不能当作安全边界。
3. **短值默认不做文本替换**（<12 字符），因此短值若被命令打印出来，不会被脱敏回引用；它仍然会注入 shell。开启「强制脱敏」的变量按 ≥4 字符参与输出替换，1–3 字符仍不匹配；短值可能误替换无关文本（路径、数字等）。该标记只影响输出方向，注入不受影响。
4. **`bash_persistent` / `terminal*` 不注入**，但同机的这些进程若被用于读取凭据文件，同样不受本插件约束。
5. **兜底只认格式**：自动检测按固定前缀/结构匹配，不做长度或熵值猜测。`Authorization: Bearer <随机串>` 这类没有格式特征的裸串不会被识别，被命令打印出来时也不会替换；达到会话预算（默认 16 条）后，新出现的格式串同样保留明文。

## 安全目标（准确表述）

- 防的是**意外泄漏**：模型正常干活时不需要知道值，日志与提示词里也不该出现值。
- 不防**主动提取**：模型只要能让命令执行，就能读到它可达的东西。这与 GitHub Actions 把 secret 注入环境变量、workflow 里 `echo` 出来即可获得是同一类边界。

## 想要更强的隔离

1. **凭据代理工具**：例如 `secret_exec` / `secret_http`——模型只给目标与参数，Host 侧注入并执行，输出回脱敏；模型不接触值。仍挡不住任意 shell。
2. **执行域隔离**：shell 以独立用户/容器运行，`$DSH_HOME` 与凭据文件对其不可读；值只注入代理执行的子进程。
3. 只要保留"同用户、任意 bash"，1 和 2 只能提高门槛，不能提供绝对保证。

## 验证

- 自动化：`node --test test/*.test.js`（值不进接口响应、短值不参与替换等用例）。
- 手工：在 Web 界面复核注入与脱敏边界（本地验收清单不入库），并确认上述"不保证"在文档里保持更新。
